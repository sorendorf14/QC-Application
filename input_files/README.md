# Input File Package Readme

## Example Input Files
You will need files like these as input, but these are just examples of AMRDC's AWS data.  Edit your AWS file formats to match these input file format or alter the code to read in your data format. Some of these files only need to have certain lines of the file altered (e.g., `filenames.csv`), where others need to be redone for your AWS information (`id.dat`) and data (e.g., `089001120.r`)

There is further information on the file naming formats, file path explanation, and how some of these are input to the code using filenames.csv in the [File Organization Wiki Page](https://github.com/sorendorf14/QC-Application/wiki/File-Organization-and-Setup). Missing data are represented by values of 444.0. Some of the input files are also output files, depending on what version of the code you are running (e.g., `hry202011raw.txt`).

Because the multiple code options depending on inputs, there are many different input files required that may have different file formats compared to each other. Additionally, the output files generated by each code are listed. A flow chart/diagram has been created to explain which input files are used in each step of the code workflow and if files are generated, what files are generated depending on which code version is utilized.

To create a file setup matching AMRDC's `.r` and `.10` input files, you can create a new code by modifying `tt_create_dotr_dot10.py` and modeling the code off the standard file formatting (lines 97-126). Column and variable information for files without column names in the file is given in a separate [readme](https://github.com/sorendorf14/QC-Application/blob/main/input_files/std_column_readme.md). 

The following table will outline each input file within this folder, an explanation of the file, and the generic file naming scheme. If you alter the naming scheme in both the code and `filenames.csv`, this will not be relevant; however, it will give you an idea of what is needed for input data to run the code (even if you have different file formatting). The first table will be the standard file format and usage. The second table will cover the different files needed for the tall tower version of the code. A [readme](https://github.com/sorendorf14/QC-Application/blob/main/input_files/elj_input_files_readme.md) gives column/variable information for all of the files without column names in the headers.

Example of standard AWS with Harry AWS (ID: 8900) for November 2020. **NOTE: AMRDC files with a four digit ID code have a leading zero.** The ID will be 08900 in filenames.
## Standard AWS File List
| Input File  | Explanation | File Naming Format |
| ------------- | ------------- | ------------- |
| 089001120.r | Input data file with standard meteorological variables (temperature, pressure, wind speed, wind direction, and relative humidity). The file naming is station ID number, month, and year abbreviation - last two digits of the year. | #####MMYY.r |
| 089001120.10 | File that is similar in format and data content to the .r file previously defined, but has two additional variables: voltage and panel temperature. If you have different file formatting, you will need to edit the code where the data are read in to match your data. If you wish to remove the option to have a .10 file, you will need to edit the code appropriately. The file naming is station ID number, month, and year abbreviation - last two digits of the year. | #####MMYY.10 |
| hry202011raw.txt | Example of a raw output file that is created when you save your QC progress. It saves the normal data, the data that were removed during the QC process, and the data that qualified for any of the QC rules. This is used as an input file when you are reloading previously QC'ed data and will denote the rules, the removed data, and the correct data. The file naming is a lowercase abbreviation, year, and month. | aaaYYYYMMraw.txt |
| id.dat  | A csv or text file with all Automatic Weather Station (AWS) information that is read in that details the station name, station ID number, abbreviated station name (AAA), latitude (decimal degrees), longitude (decimal degrees), and elevation (meters). There are three different examples of file formatting that is supported by this code. Edit to replace with all of your station data.  | id.dat |
| filenames.csv | File that is read in by `cal_file_setup.py` that details all of the file path and names to the python code, output/input directories, and input/output file names. **Make sure that you edit this file and replace the text with your directories! Make sure your input files follow the formatting in this file or edit the file to match your file formatting.** | filenames.csv |
